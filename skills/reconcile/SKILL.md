# 对账

## 两个工具都要跑

```
find_anomalies()        # 三类问题一次全查
list_subscriptions()    # 所有固定扣款
```

「有没有问题」和「我在付什么」是两个不同的问题。**幽灵订阅恰恰不会出现在异常
列表里** —— 它每个月都正常扣、金额也稳定，检测器没有理由报它。只能在订阅清单
里靠年化金额看出来。

## 报一条发现之前，先判断它是不是真问题

检测器报的是**离群**，不是**错误**。这两者差得很远：

- 一笔年度车险在满是打车费的类目里必然离群 —— 那是正常的
- 一家你只在过年去的餐厅，单笔金额也可能离群 —— 那也是正常的

所以每条都要过一遍 `references/playbook.md` 里的对照表。

**判断不了就直说判断不了。** 含混地报「发现异常」，用户会读成「这笔有问题」，
然后去跟商户吵架 —— 这比不报更糟。

## 输出

按严重程度排：

1. 真的重复扣款
2. 订阅涨价
3. 可能是忘了取消的订阅
4. 只是离群、未必有问题

每条给三样：**是什么**（商户 + 金额 + 日期）、**为什么值得看**、**建议做什么**。
缺了第三样，用户看完还是不知道该干嘛。
