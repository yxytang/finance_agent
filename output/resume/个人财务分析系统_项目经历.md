# 个人财务分析系统　2026.09—2026.10

**项目描述：** 面向个人账单核对、异常扣款识别与财务资料问答的分析 Agent，围绕“数字可核对、修改可追溯、任务可恢复”设计，实现账单事务存储、文档后台入库及可恢复的流式交互服务。

**技术栈：** Python、FastAPI、LangChain、SQLAlchemy、PostgreSQL / SQLite、Alembic、ChromaDB、Redis、BM25 / RRF、SSE、RapidOCR、Docker Compose

**主要工作：**

- **财务分析与 Agent 执行：** 通过多轮工具调用循环对接确定性查询，以 Decimal 完成金额聚合与退款处理，结合重复扣款、订阅涨价等检测工具定位异常；通过步数限制、输出截断和上下文回滚控制执行开销，并区分实际支出与预测结果。
- **账单事务与审计：** 通过 SQLAlchemy、PostgreSQL 与 Alembic 实现账单持久化及版本迁移，按“账户＋交易编号”建立唯一约束，支持重复与重叠账单幂等导入；结合乐观版本校验与事务审计，防止分类纠正相互覆盖，并保留真实双重扣款供异常检测。
- **异步文档入库：** 将 PDF、PPTX、图片的解析与本地 OCR 从 HTTP 请求中移至持久化任务队列，通过独立 worker、租约续期、任务令牌校验及有限重试处理进程中断；结合内容指纹去重和跨进程文件锁，避免重复提交及并发索引更新冲突。
- **知识检索：** 通过中文递归切分、父子块映射和 text-embedding-v4 向量化，兼顾细粒度召回与完整上下文；集成 BM25、RRF 和 gte-rerank-v2 构建可切换检索链路，以有限重试、熔断及降级隔离远程故障，并返回原文位置供核对。
- **会话与流式服务：** 通过 FastAPI、SSE 与数据库事件日志实现分析过程展示、跨 HTTP 权限确认及当前轮中断；利用单调事件序号、Last-Event-ID 与前端去重实现断线续播，持久化已完成轮的模型上下文，并在重启后标记未完成任务，避免自动重放写操作。
- **评测与验证：** 对 45 道开发题复测 3 轮，对比 BM25、向量、RRF 与重排方案，通过 Recall@5、MRR@10 和逐题消融分析识别召回退化与排序收益；补充 SQLite 与真实 PostgreSQL 的事务、并发、故障恢复测试，验证导入幂等、审计回滚及事件恢复。

## 使用说明（不放进简历）

本版本按当前仓库实现整理，没有新增未经测试的性能提升数字。45 道题为开发集，复测三轮不是 135 道独立问题，不能据此声称全量测试集效果。历史结果中纯向量整体证据召回更高，混合方案在部分多证据题的首位排序有收益，不应写“混合检索整体优于纯向量”。

当前为单 API 进程、共享工作区与可选共享 token；文档 worker 可独立运行。尚未实现多用户资源隔离、分布式 Agent 调度、任意工具写入恰好执行一次，也未完成 QPS/吞吐压测。SSE 传输工具执行事件与最终答案，不是模型 token 流。上传成功表示原件和词法索引就绪，远程向量化在后续检索时完成。

项目为个人实现，宜写“设计与实现”“本地集成验证”，不写实际生产用户量或企业上线收益。若简历篇幅有限，优先保留财务分析、账单事务、异步入库、会话恢复四条，再按岗位侧重选择检索或评测内容。
